# PLE 与匹配 CGC

2026-11-18 实现。依据 [PLE 原论文](https://doi.org/10.1145/3383313.3412236)
§4.1–4.2、公式 (2)–(7)、图 4–5 实现内部信息流。

`hydrostate/models/cosa/ple.py` 的每层有 Coverage、SM、ET 私有专家和共享专家。
任务门控只混合本任务私有专家与共享专家；中间层共享门控混合所有任务私有专家及
共享专家。下一层各自接收上一层对应门控输出，所有更新同时发生。最后一层无共享
门控，避免没有监督消费者的参数。

首轮采用两层、宽度 256/128，任务塔宽度 64；每组一个专家。
论文 §5.1.3 使用两层比较，§5.3 的专家利用分析使用每组一个专家；这不是宣称
恢复作者所有调参结果。匹配 CGC 使用同一实现，设为单层宽度 256。
两者使用相同的时序状态和任务头，新增层改变容量，应同时报告参数量及吞吐。

推荐任务 MLP 改为逐像元 1×1 Conv + ReLU；门控为逐像元线性变换 + softmax。
输入仍为 OlmoEarth 和 CoSA 的共享目标时间状态；输出保留当前空间任务头和物理约束。
这保留了完整 PLE 层级及连接关系，但不是原推荐数据集、输入或优化器的逐项复现。
参考核查过的 LibMTL PLE ResNet 版本没有独立演化的共享门控流，故未直接采用其代码。

入口：`configs/hydrostate_joint_ple.py`、`configs/hydrostate_joint_cgc_matched.py`。
原 `hydrostate_joint_cgc.py` 的空间残差专家与全局门控不变，作为独立历史基准。
测试覆盖解析门控加权、最后一层私有隔离、中间共享流跨任务梯度、全缺测屏蔽，
以及真实小型编码器上的产品／站点混合损失。
